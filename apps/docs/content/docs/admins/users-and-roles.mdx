Manage users under **Administration → Users** (`/admin/users`).

## Roles

NextCRM has three roles:

| Role | Users | CRM records | Projects | Reports | Settings |
|---|---|---|---|---|---|
| `admin` | create, read, update, delete, change role, activate, deactivate | full access | full access | read, export | read, update |
| `manager` | read | full access | full access | read, export | read |
| `user` | read | read | read | read | read |

These are the permission statements defined in `lib/auth-permissions.ts`. In addition:

- Only admins can open the administration panel.
- Admins and managers work with all CRM records. For the `user` role, edits and reports are limited to records the user owns: records assigned to them or created by them (for accounts, also accounts they watch).

Older instances may still have the legacy role values `member` and `viewer`. NextCRM treats `member` as `manager` and `viewer` as `user`.

## User status

Every user has a status:

| Status | Meaning |
|---|---|
| `ACTIVE` | Can use the app. |
| `PENDING` | Signed up but not yet approved. Sees a waiting page after sign-in. |
| `INACTIVE` | Deactivated by an admin. Sees an "inactive" page after sign-in. |

## How users get in

### Invitation

At the top of the Users page, enter a name, email and language and send the invitation. NextCRM creates the user with role `user` and status `ACTIVE` and sends an invitation email through Resend. Inviting fails with an error if no Resend key is configured.

### Self sign-up

Anyone who reaches the sign-in page can request a code for a new email address, or use "Sign in with Google" if it is configured. A new account is created with status `PENDING`. All admins get a notification email through the SMTP server (`EMAIL_HOST`); the notification links to `/admin/users`. Approve the user by activating them.

If there are no users at all, the first account that signs up becomes `admin` and `ACTIVE`. With Docker the seed already creates the first admin, so this only matters for manual installs.

## Managing a user

Open the row menu in the user table:

- **Copy ID**
- **Activate**: sets status `ACTIVE` and sends the user an email through SMTP.
- **Deactivate**: sets status `INACTIVE`.
- **Set Role**: `admin`, `manager` or `user`. You cannot remove your own admin role.
- **Delete**: removes the user after confirmation.

### Message all users

**Send mail to all** sends a message with a title and body to every user in the table, whatever their status.

## API tokens

Each user can create personal API tokens for the MCP server in their profile (Developer tab). Tokens start with `nxtc__`, are stored only as a SHA-256 hash, can have an expiry date, and act with the role of the user who created them. A user can have at most 10 active tokens. See [MCP server](/docs/developers/mcp).

<Callout type="warn">
  Deactivating a user does not revoke their API tokens, and the MCP server does not check user status. Tokens can only be revoked by their owner. To cut off a departing user completely, ask them to revoke their tokens first, or delete the user (tokens are deleted with the user).
</Callout>
