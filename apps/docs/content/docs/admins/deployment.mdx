title: Deployment
description: Run NextCRM on Coolify, Portainer or a build-pack platform, behind a reverse proxy with HTTPS.

Any platform that can run a Docker Compose stack can run NextCRM. The repository has two compose files:

| File | Use it for |
|---|---|
| `docker-compose.yml` | A local trial or a single host. Publishes port 3000, has defaults for every password, passes only a subset of variables to the app. |
| `docker-compose-coolify.yml` | Platforms that inject environment variables and route traffic through their own proxy. Every deployment-specific value is a `${VAR}`, required secrets fail the deploy if missing, no host ports are published. |

## Coolify

<Steps>
<Step>

### Create the resource

Point Coolify at the repository and choose the **Docker Compose** build pack with compose location `/docker-compose-coolify.yml`.

</Step>
<Step>

### Set the required variables

The deploy fails without these four:

- `POSTGRES_PASSWORD`
- `MINIO_ROOT_PASSWORD`
- `BETTER_AUTH_SECRET` (`openssl rand -base64 32`)
- `EMAIL_ENCRYPTION_KEY` (`openssl rand -hex 32`)

Set them once and never change them. A new `BETTER_AUTH_SECRET` logs everyone out. A new `EMAIL_ENCRYPTION_KEY` makes stored keys and mailbox passwords unreadable.

</Step>
<Step>

### Set the instance URL and email

- `APP_URL`: the public URL, for example `https://crm.example.com`. The compose file uses it for both `NEXT_PUBLIC_APP_URL` and `BETTER_AUTH_URL`.
- `ADMIN_EMAIL`: the first admin's address.
- `RESEND_API_KEY` and `EMAIL_FROM` (a verified Resend sender), so login codes can be sent.

Add optional keys from the [configuration reference](/docs/admins/configuration) as needed. `docker-compose-coolify.yml` passes `RESEND_FROM_EMAIL`, `RESEND_WEBHOOK_SECRET`, `EMAIL_HOST`, `EMAIL_USERNAME`, `EMAIL_PASSWORD`, `OPENAI_API_KEY`, `GOOGLE_ID`, `GOOGLE_SECRET`, `GOOGLE_CALENDAR_CLIENT_ID`, `GOOGLE_CALENDAR_CLIENT_SECRET`, `FIRECRAWL_API_KEY`, `E2B_API_KEY` and the Inngest settings. Anything else (for example `ANTHROPIC_API_KEY` or `NEXTCRM_TOKEN`) must be added to the file's `app.environment` block, or set in the admin panel where that is possible.

</Step>
<Step>

### Assign domains

Assign your domain to the `app` service, port 3000. If browsers need to reach uploaded files, assign a second domain to the `minio` service, port 9000, and set `MINIO_PUBLIC_URL` to it (see [File storage behind a proxy](#file-storage-behind-a-proxy)).

</Step>
</Steps>

## Portainer, Dockge and similar

Paste a compose file into a new stack and set variables in the platform UI. Variables set there fill the `${...}` placeholders the same way a `.env` file does.

- `docker-compose.yml` works as is, but only passes some variables to the app and hard-codes `localhost:3000` as the URL. See [Which variables reach the app](/docs/admins/install-docker#which-variables-reach-the-app).
- `docker-compose-coolify.yml` passes almost everything, but uses `expose` instead of `ports`. Add a `ports:` entry to the `app` service, or attach your reverse proxy to the stack's network.

## Build-pack platforms

`nixpacks.toml` makes Nixpacks (used by Coolify's Nixpacks build pack) install a current pnpm. Platforms that build from source run the package scripts:

- `pnpm build` runs `prisma generate`, `prisma migrate deploy` and `next build`. Migrations therefore run during the build, and the build needs `DATABASE_URL` pointing at a reachable database.
- `pnpm start` runs `next start`.

In this mode nothing is bundled. You provide PostgreSQL with pgvector, S3-compatible storage and an Inngest server yourself, set every required variable, and seed the first admin once with `pnpm prisma db seed` (it uses `TEST_USER_EMAIL`).

## Reverse proxy and HTTPS

The app listens on plain HTTP, port 3000. Terminate TLS in front of it (Coolify's proxy, Traefik, Caddy, nginx) and forward to the app.

- Set `BETTER_AUTH_URL` and `NEXT_PUBLIC_APP_URL` to the public `https://` URL. Email links, the Google sign-in and Calendar redirect URIs, and the Calendly webhook URL are built from them.
- Some responses are streamed: the interactive enrichment endpoints use server-sent events, and the MCP server offers an SSE transport at `/api/mcp/sse`. Turn off response buffering for the app if your proxy buffers by default.
- Keep Postgres, MinIO's console and the Inngest dashboard off the public internet.

## File storage behind a proxy

Browsers talk to object storage directly:

- **Uploads.** The app returns a presigned `PUT` URL signed for `MINIO_ENDPOINT`, and the browser uploads the file to that URL.
- **Downloads and previews.** File links are built as `<NEXT_PUBLIC_MINIO_ENDPOINT>/<bucket>/<key>`, and the browser loads them from there.

Both compose files set `MINIO_ENDPOINT` to `http://minio:9000`, an address only containers can resolve. For uploads and file links to work from a browser:

1. Publish MinIO's S3 port (9000) under a domain browsers can reach, for example `https://files.example.com`.
2. Set `MINIO_ENDPOINT` and `NEXT_PUBLIC_MINIO_ENDPOINT` to that URL (with `docker-compose-coolify.yml`, `NEXT_PUBLIC_MINIO_ENDPOINT` comes from `MINIO_PUBLIC_URL`; `MINIO_ENDPOINT` is fixed in the file and needs an edit or override).
3. Decide how files are read. The entrypoint creates the bucket but sets no access policy, and file links are plain URLs without a signature. Object keys are random UUIDs.

<Callout type="warn">
  The entrypoint's bucket check always uses `http://` with the host taken from `MINIO_ENDPOINT`. With an `https://` endpoint it may fail and log `WARN: Could not create MinIO bucket`. In that case create the bucket once by hand (for example in the MinIO console).
</Callout>

## Migrations on start

With the Dockerfile, the entrypoint runs `prisma migrate deploy` on every start, before the server starts. If a migration fails, the container exits and the platform restarts it; check the app logs. The seed runs only when the `Users` table is empty.

The Dockerfile build generates the plugin registry (`scripts/plugins/generate-registry.mjs`), runs `prisma generate` and `next build` with placeholder values. Real secrets are only needed at runtime.
