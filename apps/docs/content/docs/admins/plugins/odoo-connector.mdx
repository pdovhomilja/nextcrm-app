---
title: Odoo connector
description: Import customers, their people and the product catalog with price lists from an Odoo ERP and keep them current.
---

The **Odoo connector** plugin (`odoo-connector`) reads customers from an Odoo ERP and keeps them in the CRM as accounts, with their people as contacts. It also brings in Odoo's product catalog and chosen price lists, so the CRM prices exactly like Odoo. It only reads from Odoo: it never creates or changes anything there.

## What it does

- Every Odoo customer (a company or a person with a customer rank above zero, no parent, active) becomes an account. An existing account is reused when it matches (see below); otherwise a new one is created.
- People under those customers (child contacts of type "contact") become contacts on the account.
- After the first import, the plugin checks Odoo for changed partners every `syncMinutes` minutes and updates the CRM.

## Before you start

- Odoo 18 or later (the plugin uses Odoo's JSON-2 API).
- An Odoo user for the CRM with an API key. It needs read access to contacts (partners), countries, users, products, product categories, taxes, price lists and sales orders (to compare prices). It needs no write access.

## Install and settings

Install it under **Admin → Plugins → Odoo connector**.

| Setting | Default | Effect |
|---|---|---|
| `url` | none | The Odoo address, starting with `https://`, for example `https://odoo.example.com`. |
| `database` | none | The Odoo database name. |
| `syncMinutes` | `15` | Minutes between syncs, 5 to 1440. The check runs every 5 minutes, so a sync can start up to 5 minutes later. |
| `defaultCountry` | `CZ` | Two-letter country code for customers without a country in Odoo. |
| `dryRun` | on | While on, the sync only writes to the plugin log what it would create or change, and the scheduled sync is paused: use **Sync now**. |
| `priceLists` | empty | The Odoo price lists to import: their Odoo ids, separated by commas, for example `242, 245`. See [Catalog](#catalog). |

The secret `apiKey` holds the Odoo user's API key. It is stored encrypted.

## Dry run first

A new install starts in dry run. Use **Test connection** to check the address, database and key: it shows the Odoo version and the API user's name. Then click **Sync now** and read the plugin log: it lists every account and contact the sync would create or update, and every customer that matches more than one account. When the list looks right, turn `dryRun` off in the settings and click **Sync now** again.

## How customers are matched

For each Odoo customer the plugin tries, in this order:

1. an account it already linked to this customer;
2. an account with the same country and registration number (spaces are ignored; Czech numbers are compared with leading zeros to 8 digits);
3. an account with the same VAT number;
4. otherwise it creates a new account.

When two or more accounts match in step 2 or 3, or the matching account is already linked to another Odoo customer, the plugin links nothing and lists the customer under **Customers matching more than one account** on the plugin's admin page. Fix it in the CRM (correct or remove the duplicate) and the next sync links it, even if nothing changed in Odoo.

## Owners

A new account gets an owner when the customer's salesperson in Odoo has the same email (upper or lower case does not matter) as an active CRM user. Otherwise the account has no owner and appears on the **Needs owner** page (under Plugins in the menu, for managers and admins), with the Odoo salesperson's name. A sync never changes the owner of an account that already exists.

## What Odoo controls

Odoo wins for these account fields: name, registration number, VAT number, billing street, city, postal code, region, country, email and phone. When a customer changes in Odoo, the next sync writes these fields to the account, even if someone edited them in the CRM. A field that is empty in Odoo never clears a value filled in the CRM.

The sync never touches anything else: the owner of an existing account, the shipping address, the price list, notes, activities and all other fields. The account's **Odoo** panel shows the link to the Odoo partner and when it was last synced.

## Archived customers

When a customer is archived in Odoo, or stops being a customer, nothing is deleted in the CRM. The account's Odoo panel shows the change. If the customer becomes active again, it syncs as before.

## Catalog

Every sync also brings in the catalog:

- **Categories:** all Odoo product categories, as a tree.
- **Products:** every sellable Odoo product variant becomes a product, with its SKU, price, cost, sales tax, unit and category. A variant that is archived or no longer sold in Odoo is archived in the CRM, never deleted.
- **Price lists:** the lists in `priceLists`, with all their rules. Lists they build on (for example a base list that is archived in Odoo) come along automatically as inactive lists, marked **Base for other lists**; reps don't pick them, but prices are computed through them.
- **Account price lists:** a linked account gets its Odoo customer's price list, when that list is imported. The account's Odoo panel shows the Odoo list, or that it is not imported.

Products, categories and these price lists are read-only in the CRM: change them in Odoo. To choose lists, click **Load price lists** on the plugin's admin page: it shows every Odoo list with its id. Put the ids in `priceLists` and save.

Rules the CRM cannot use are listed on the admin page under **Rules the CRM cannot use**. An Odoo variant whose SKU a CRM product already uses is not imported; the plugin log names it and the next syncs try again until one of the two SKUs changes.

## Compare with Odoo

**Compare with Odoo** checks that the CRM prices like Odoo. For each list in `priceLists` it picks up to 20 products, covering the kinds of rules on the list, and prices each at quantity 1, at the minimum quantity of the rule that prices it, and one below. Odoo prices the same lines without saving anything. The admin page then shows, per list, how many prices matched, and every difference with the reason:

- **price rule:** the CRM and Odoo apply a rule differently. Report it.
- **exchange rate:** Odoo converted the product price into the list currency with its rate of the day, and the CRM's rate for that day differs. Keep the CRM's exchange rates in line with Odoo's.

## Failures

**Sync now** and **Compare with Odoo** are queued and start within 5 minutes. A failing sync is logged in the plugin log with the reason, for example when Odoo rejects the API key, or denies access to a model the Odoo user cannot read (the log names it). The next run repeats everything since the last good run; a customer or person that failed on its own is tried again on every run until it succeeds. After three failed runs in a row, admins get one email.
